# 知隙 GapCoach — 一页纸简报

## 一句话

一个越用越懂你的复习教练：用 seekdb 找到该复习的内容，用 PowerContext 记住你为什么需要复习它。

## 目标用户

需要反复复习、但不知道自己哪里薄弱的大学生/备考者。首个演示场景为「数据库系统概论」课程。

## 真实痛点

1. 复习从第一页开始，时间花在已经会的内容上。
2. 错题、薄弱点、复习进度散落在笔记和不同会话里，下次接不上。
3. 不知道自己“会了什么、还差什么”，缺少今天就能执行的下一步。

## 解决方案

- **seekdb**：存课程资料、知识点、题目和作答记录；按课程/知识点过滤 + 关键词/全文 + 语义相似做混合检索，推荐“现在最该练的题”。
- **PowerContext**：按学习者 + 课程保存薄弱点、掌握度、最近复习时间和偏好；每次答题后更新，下次打开直接恢复进度。
- **前端**：诊断 → 今日复习 → 答题反馈 → 进度，一条闭环，不做登录和多租户。

## 核心闭环

```text
选择课程
  → 5 道诊断题
  → 判分 + 识别薄弱点
  → 写入 PowerContext
  → seekdb 检索推荐题
  → 逐题作答 + 解析 + 来源
  → 更新掌握度/薄弱点
  → 下次打开继续
```

## 差异化

不是“又一个题库”：推荐理由来自两处真实数据——seekdb 的检索结果和 PowerContext 的记忆。用户能看到“为什么今天练这道题”，也能看到自己的薄弱点如何随练习变化。

## 3 天最小版范围

- 一门课程、一个本地 learner_id（不做登录）。
- 诊断、今日复习、答题反馈、简单进度。
- seekdb 检索 + PowerContext 读写。
- `verify.py` 证明记忆复用。
- Qoder Sites 展示站 + README + 开发记录。

## 明确不做

- 账号/权限/多租户/支付。
- 复杂 PDF/OCR。
- 大规模题库/爬虫/实时协作。
- 必须付费模型才能跑通的核心流程。

## 成功指标

- 首次诊断后能识别至少 2 个薄弱点。
- 第二次打开时，复习计划包含上次的薄弱点（记忆复用）。
- 3–5 位真实用户完成一轮；记录前后复习准备耗时。
- 网站可访问、项目可按 README 复现、技术作用有日志证据。
