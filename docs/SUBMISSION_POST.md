## 一、自我介绍

我们是北京邮电大学的两位本科生，一个偏产品，一个偏工程。

事情的起因很朴素：期末周的时候，我们对着题库刷了两百多道题，最后只知道自己"对了 78%"。哪 22% 错了、错在哪个知识点、下一步该看教材的哪一节，题库一个字都没说。于是我们决定自己做一个"会告诉你下一步干什么"的复习工具——这个想法在 2026 年 10 月做成了第一版（当时是为了另一个技术赛道，Python 后端 + 嵌入式向量库 + 本地记忆服务），这次为了高校创造力大赛，我们用 Qoder 把它重做成了一个**点开链接就能玩的纯浏览器应用**。

## 二、这个作品是什么

一句话：**先诊断，再给证据，最后记住你**——一个把混合检索和学习记忆整套引擎跑在浏览器里的复习教练。

它想解决的是复习里最难的三件事：

| 复习时的困惑 | 大多数题库 | 知隙 GapCoach |
| --- | --- | --- |
| 我到底卡在哪 | 只说"错了几道" | 定位到知识点，给出掌握度和"为什么先补它" |
| 下次先看什么 | 没有下一步 | 今日计划按薄弱程度排序，每组附检索出的原文材料 |
| 上次的错能不能带过来 | 每次从零开始 | 写进学习记忆，下次同名进入自动恢复 |

一条闭环：

```text
10 题诊断 → 掌握度与薄弱点 → 写入学习记忆
      ↓                              ↓
浏览器内混合检索材料与练习 ← 今日计划按薄弱程度排序
      ↓
作答 → 判分 + 原文证据 + 掌握度变化 → 新记忆 → 下次继续
```

典型场景：期末前只有 40 分钟。打开链接，3 分钟做完 10 题诊断，报告直接告诉你两个薄弱点和先补哪个的理由；今日计划给你 3 组任务，每组 2 段材料 2 道练习，标注预计时长；做错一题，反馈里带着可以引用的原文段落、掌握度从 26 掉到 11 的过程，以及"你上次也在这里错过"。

核心能力：

- **入学诊断**：10 题覆盖 5 个知识模块（示例课程《数据库系统概论》，5 知识点 / 15 段材料 / 30 题），支持键盘 `1–4` 选择、`Enter` 继续、回看上一题。
- **诊断报告**：掌握度条 + 真正的薄弱点 + 证据句（例如"你在「并发控制与隔离级别」上只答对 0/2 题"），并列出本次写入的学习记忆（含 artifact 编号）。
- **今日计划**：最多 3 组，按"掌握度低 + 最近错得多"排序，每组材料都公开检索分与薄弱加权分。
- **练习反馈**：判分、解析、出处到章节的原文证据、掌握度变化、相似错题提醒。
- **学习记忆与恢复**：重新输入同一称呼即恢复上次状态；进度页有完整记忆时间线（计划快照 / 会话摘要 / 薄弱点 / 进步记忆，均带 artifact 与 revision）。
- **技术轨迹页**：把每次检索与记忆读写的 `kind / action / detail` 逐条摊开，还能输入任意问题现场跑一次混合检索，看分数构成。

## 三、为什么做

第一版做完之后，我们其实挺满意：后端跑得通，20 项端到端断言全过。但它有个致命问题——**别人用不了**。要装 Python、建虚拟环境、起两个服务，评委看到 README 就关掉了。

中间我们试过的方案，以及为什么放弃：

1. **部署后端到云上**：向量库和记忆服务都是本地嵌入式进程，搬到云上要么换托管服务（引入外部依赖和 Key），要么容器化（评审仍然需要等待启动）。为了让"点开就能玩"付出这么多架构成本，不划算。
2. **只做个演示视频/截图站**：能展示，但评委没法自己输入称呼、自己答错一题、自己看到掌握度掉下来。复习工具的价值只有在交互里才成立。
3. **把检索和记忆都砍掉，退化成普通题库**：那就变成了我们一开始想解决的那个"只说对了几道"的东西，没意义。

最后选的路：**把整套引擎移植进浏览器**，语义一个字不改。所以定了几条设计原则：

- **规则必须可核对**：掌握度初始 50，诊断 ±12，练习答对 +10（连对 ≥2 时 +15）、答错 −15；薄弱 = <60 且已作答；稳固 = ≥85 且连对 ≥3，此时薄弱记忆**解除**而不是永久贴标签。这些数字与原版后端完全一致，也直接写在 README 里。
- **分数必须公开构成**：每条材料都带 `score_parts`（检索分 / 薄弱加权分），不藏黑箱。
- **数据必须留在用户手里**：全部落 localStorage，不上传任何服务器，不接第三方统计。
- **不做的功能**：不做账号系统、不做云端同步、不做 AI 生成解析（题库自带人工写的解析，避免不可核对的内容）、不虚构使用人数和提效比例。

### 技术上到底做了什么

第一版是 Python 后端（FastAPI + 嵌入式 seekdb + PowerContext 本地记忆服务）。这一版把同样的语义完整移植进浏览器，零依赖、零构建、零 API Key：

- **混合检索**（`engine/retrieval.js`）：全文通道做中文分词（unigram + bigram + ASCII 词）包含匹配打分；向量通道做特征哈希 embedding 的余弦相似度；两路结果 **RRF 融合**（k=20，窗口 8）后按知识点过滤；综合分 = 检索分 × 0.72 + 薄弱加权 × 0.28。同一个问题，对不同掌握度的学生返回不同排序。
- **中文 embedding**（`engine/embed.js`）：字符 unigram + bigram + ASCII 词 → FNV-1a 特征哈希 → 384 维 L2 归一化，纯本地计算。
- **学习记忆**（`engine/memory.js`）：weakness / strength / session / plan 四类，带 artifact 与 revision，支持生命周期解除；接口语义复刻自原版。
- **进度存储**（`engine/storage.js`）：作答与掌握度落 localStorage；相似错题 = 错题文本向量余弦 Top-K。
- **教练逻辑**（`engine/coach.js`）：诊断选题、计划排序、判分反馈、跨会话恢复。

数据落点：

| 数据 | 位置 |
| --- | --- |
| 题库（5 知识点 / 15 材料 / 30 题） | `assets/data/content.json`，随静态站分发 |
| 作答与掌握度 | localStorage `gapcoach.store.v1` |
| 学习记忆 | localStorage `gapcoach.memory.v1` |
| 会话状态 | localStorage `gapcoach.session.v1` |
| 调用轨迹 | 内存环形缓冲 200 条 |

本地运行：`node scripts/serve.mjs`（零依赖静态服务器），打开 `http://127.0.0.1:8000`。

## 五、用 Qoder 做出来的过程

两轮迭代都主要由 Qoder 完成开发，我们负责判断和验收。

**第一轮（2026-10，原版后端）**：规则拆解、技术验证（向量库建库/混合检索、记忆 Scope/lifecycle 最小闭环）、后端与 7 个视图前端实现、实机调试、20 项端到端断言、Sites 发布。

**第二轮（2026-11，本次换壳）**：

| 环节 | 交给 Qoder 的部分 | 我们做的判断与修改 |
| --- | --- | --- |
| 仓库重建 | 在新机器上整理为独立 git 仓库，基线提交保留旧版全部代码 | 决定基线不删旧实现，作为对照与迁移依据 |
| 引擎移植 | 5 个 Python 模块逐一移植为 9 个浏览器 ES 模块 | 要求规则与分数语义不变，不接受"顺手优化"数值 |
| 接口兼容 | `api.js` 改为薄委托层 | 决定 7 个视图只换文案，把回归面压到最小 |
| 验收 | 36 项浏览器内引擎断言 + 实机走查 | 坚持要在**线上发布后的站点**再跑一遍完整闭环 |
| 交付 | Sites 公开发布、GitHub 推送、文档与截图归档 | 确认公开访问策略、检查仓库内无任何真实凭据 |

**三个关键迭代**

1. **先定验收标准，再动手移植。** 迁移前先把原版后端的 20 项断言翻译成浏览器内可跑的 36 项断言（诊断识别薄弱点、计划薄弱优先、答错掌握度 26→11 且带证据与记忆事件、同名恢复、个性化排序、health 返回 15 材料/30 题…）。有了这套标准，移植就不是"看起来能用"，而是逐条对账。
2. **薄委托层而不是重写视图。** 前端 7 个视图原本直接调 `api.js`。我们没有让它们改调新引擎，而是把 `api.js` 改成签名不变的委托层。代价是多一层间接，收益是回归面只有引擎本身。
3. **把"可核对"当成一个功能来做。** 技术轨迹页不是事后补的展示，它是我们验收时用来定位问题的工具——每次检索的通道、过滤条件、返回分数，每次记忆读写的 kind/action/detail，都逐条摊开。评审也能用同一页核对我们的说法。

**我们改过的问题**

- `content_ready` 轨迹重复：多个视图并发 `fetch` 同一份 `content.json`，各自记一条轨迹。改为缓存 in-flight Promise 并在失败时重置。
- 轨迹时间戳显示成 `-11-06T15:48:40`：切片下标差一位（`slice(4,19)`），改为 `slice(5,19)` 并把 `T` 换成空格。
- 站点发布后发现旧地址属于重装系统前的账号、当前账号已不可访问：没有试图顶替旧站，而是在当前账号下新建站点并同步更新全部文档里的链接。

**数据与边界**

- 在线版：36/36 浏览器内引擎断言通过；发布后用云浏览器在线上实跑完整闭环（首页与题库加载 → 诊断 → 报告 → 计划 → 练习答错反馈 → 进度 → 轨迹）全部正常。
- 原版后端：20/20 端到端断言（含一次干净房间复现），证据归档在 `docs/legacy/` 与 `docs/verification/`。
- 使用效果：**尚未收集真实外部用户数据，因此不写人数、提效比例或用户评价**。
- 隐私与合规：不收集访问者个人信息，不接第三方统计；仓库与站点不含任何真实 API Key、密码或个人身份信息；课程材料与 30 道题为我们自写的演示内容，不含教材/论文原文复制。
